System administration · eight-service containerised infrastructure

DockerDocker ComposeNginxMariaDBWordPressRedisTLS

The problem

Deploy a production-like WordPress site where every service is isolated, connections are protected, and data survives container restarts — with every image built from a custom Dockerfile.

What I built

A Docker Compose stack of eight services built on Debian Bullseye: the WordPress core plus Redis caching, FTP, Adminer, a static website and cAdvisor monitoring.

Creadlinefork / execvepipessignals

The problem

Rebuild a real Unix shell: read a command line, understand its grammar — quotes, pipes, redirections, logical operators — and run it exactly the way bash would.

What I built

06 — Systems

Philosophers

Concurrency · the dining philosophers problem, twice

CpthreadsmutexesforkPOSIX semaphores

The problem

N philosophers share N forks around a table. Each must eat before starving — without deadlocks, data races, or a death being reported a few milliseconds late.

What I built

Two complete simulations: one with threads and mutexes, and a bonus version where each philosopher is its own process synchronised with named semaphores.

Engineering highlights

  • Threads: each philosopher runs in a pthread; forks are mutexes.
  • Race-free state: every shared value read and written through mutex-guarded helpers.
  • Processes: bonus forks one process per philosopher, with semaphores for forks, printing and meal counts.
  • Timing: millisecond-accurate sleeps and a monitor that reports death on time.

Darkly

BashcurlHTTPOWASP

The problem

A deliberately vulnerable web app. Find how small mistakes expose private data, hand over other people's accounts, or give control of the database — then prove it and explain the fix.

What I built

A security journal of 13 chapters: for each finding, how it was found, its impact, a reproducible demonstration, and how to prevent it.
